src/app/core/interceptors/auth.interceptor.ts

authInterceptor
Type : HttpInterceptorFn
Default value : (req, next) => { if (!req.url.startsWith(environment.supabaseUrl)) { return next(req); } const auth = inject(AuthService); const router = inject(Router); let headers = req.headers.set('apikey', environment.supabaseAnonKey); const token = auth.accessToken(); if (token) { headers = headers.set('Authorization', `Bearer ${token}`); /* Añade cabeceras de autorificación */ } /** Por seguridad, aplicando la regla del peor caso posible, si una persona no cumple los requisitos (en este caso que los tokens no sirvan) lo que se hace es denegarle el acceso Es como con un semáforo, si hay un fallo no puede quedarse en verde, porque entonces sería un caos, lo que tiene que hacer es ponerse en rojo para evitar que ningún coche pase y así evitar cualquier posible accidente */ return next(req.clone({ headers })).pipe( catchError((error: HttpErrorResponse) => { if (error.status === 401 && token) { void auth.logout().then(() => router.navigateByUrl('/login')); } return throwError(() => error); }), ); }

Lo que consigo con esto es interceptar cada petición de HttpClient antes de que salga:

  • Si la URL no es de mi proyecto de Supabase, la deja pasar sin tocarla
  • Si lo es, le añade la cabecera apikey con la clave pública
  • Si hay sesión, añade también Authorization: Bearer . Con ese token, Supabase sabe quién eres y aplica las políticas RLS
  • Si el servidor responde 401 (token caducado o inválido), cierra la sesión y te manda al login

src/app/core/guards/role.guard.ts

roleGuard
Type : unknown
Default value : (role: Role): CanActivateFn => async () => { const auth = inject(AuthService); const router = inject(Router); await auth.waitUntilReady(); return auth.profile()?.role === role ? true : router.createUrlTree(['/tareas']); /* Si no tienes el rol exigido te redirige a /tareas */ }

El role.guard comprueba que el rol del perfil es el que exige la ruta Es una función que recibe el rol y devuleve el guard roleGuard('admin') Es como si preguntara "¿tienes el rol necesario?" Se usa en /dashboard, junto con authGuard, de forma que primero se comprueba la sesión y luego el rol Por ejemplo, Ana (usuario estándar) escribe /dashboard a mano. Tiene sesión, pero no es admin, así que vuelve a tasks
